How to deploy an app

An app is a Docker Compose file, a Dockerfile, or both, plus any text files the build needs. Every machine runs it, and it's reachable at https://<name>.billybishop4-workers.xyz (sent to a machine where it's healthy), and machine n also serves it at https://<name>-n.billybishop4-workers.xyz. Each deploy is a new version, and every machine switches to it at once.

From this page

  1. Click New project at the top.
  2. Name: lowercase letters, digits and dashes, such as my-app.
  3. Replicas: how many machines should run it (default 1), or all. The control plane picks the machines with the most free CPU and memory.
  4. Port: the port your app listens on. You can leave it empty if the compose file sets x-runner.port; with no port the app runs but isn't reachable from outside.
  5. Paste a Docker Compose file, a Dockerfile, or both. Use Add a file for anything the Dockerfile COPYs (source files, configs).
  6. Click Deploy. The dots on the project card turn green as each machine reports healthy. A red dot shows the error; fix it and deploy again.

To change an app, open it and click Edit. To roll back, pick an earlier version in the editor, click Load, then Deploy.

With the API

Send JSON to PUT /admin/api/projects/<name>. No token is needed. Scripts that have the admin token can use /api/… instead, with Authorization: Bearer <token>; the routes and bodies are the same.

FieldWhat it is
composeThe compose file, as text. Required unless you send dockerfile.
dockerfileA Dockerfile, as text. On its own it becomes a one-service app that builds it and publishes port.
files{"path": "text", …}: other files, next to the compose file (e.g. src/main.py, web/Dockerfile).
portThe port the app listens on (or set x-runner.port in the compose file).
replicasHow many machines run it (or x-runner.replicas): a number, or "all". Default 1. Each replica is placed on the machine with the most room and stays there until that machine goes away.
state"stateless" (default) or "stateful" (or x-runner.state). A stateful replica keeps a directory in the fleet's storage that follows it wherever it runs.
dataStateful only: the directory inside the container where the app keeps its state, like "/data". It's mounted there in every service.
storageStateful only: how much a replica may keep, in MB (or "200M"). Default 100, max 500. Over it, the data turns read-only until you raise the limit or clear it.

Limits: 30 files, 250 KB in all, text files only. Ports 2019 and 19080 are taken. Every build: needs its Dockerfile among the files.

1. A published image (compose only)
curl -X PUT https://control.billybishop4-workers.xyz/admin/api/projects/whoami \
  -H 'Content-Type: application/json' \
  -d '{"port": 8080, "replicas": 3, "compose": "services:\n  web:\n    image: traefik/whoami\n    command: [\"--port\", \"8080\"]\n    ports: [\"8080:8080\"]\n    restart: unless-stopped\n"}'
2. Just a Dockerfile
curl -X PUT https://control.billybishop4-workers.xyz/admin/api/projects/hello \
  -H 'Content-Type: application/json' \
  -d '{"port": 9000, "dockerfile": "FROM python:3.12-alpine\nCMD [\"python\", \"-m\", \"http.server\", \"9000\"]"}'
3. A stateful app (keeps data)
curl -X PUT https://control.billybishop4-workers.xyz/admin/api/projects/notes \
  -H 'Content-Type: application/json' \
  -d '{"port": 8080, "state": "stateful", "data": "/data", "storage": 200, "compose": "services:\n  app:\n    image: ghcr.io/you/notes\n    ports: [\"8080:8080\"]\n    restart: unless-stopped\n"}'

Or in the compose file itself: x-runner: { state: stateful, data: /data, storage: 200M }. The app just reads and writes /data; a file is safe in the fleet's storage (Cloudflare R2) once the app closes it. When the replica moves or its machine goes, the next machine mounts the same data. Databases that keep a file open all the time (SQLite, Postgres) aren't a fit for this; files are.

4. Your own code from files on disk

Escaping files into JSON by hand is painful; let jq build the body:

# my-app/Dockerfile, my-app/app.py
jq -n --rawfile df my-app/Dockerfile --rawfile app my-app/app.py \
  '{port: 8000, dockerfile: $df, files: {"app.py": $app}}' |
curl -X PUT https://control.billybishop4-workers.xyz/admin/api/projects/my-app \
  -H 'Content-Type: application/json' --data-binary @-
# a compose file with its own build folder: compose.yaml has  build: ./web
jq -n --rawfile c compose.yaml --rawfile d web/Dockerfile --rawfile s web/server.js \
  '{compose: $c, files: {"web/Dockerfile": $d, "web/server.js": $s}}' |
curl -X PUT https://control.billybishop4-workers.xyz/admin/api/projects/my-app \
  -H 'Content-Type: application/json' --data-binary @-
Check on it, roll back, turn off
B=https://control.billybishop4-workers.xyz/admin/api

curl $B/status                           # every project and machine; per-machine state is under runs[].projects
curl $B/projects/my-app                  # the current spec and the list of versions
curl $B/projects/my-app?version=2        # an earlier version

# roll back: send version 2's spec again (it becomes a new version)
curl -s "$B/projects/my-app?version=2" | jq '{compose, files, port}' |
  curl -X PUT $B/projects/my-app -H 'Content-Type: application/json' --data-binary @-

curl -X POST $B/projects/my-app/disable  # stop it everywhere, keep its versions
curl -X POST $B/projects/my-app/enable
curl -X DELETE $B/projects/my-app        # delete it and all its versions

A deploy answers with the project's state. Machines pick the change up within about 20 seconds; builds can take a few minutes. Then open https://my-app.billybishop4-workers.xyz, or one machine's copy at https://my-app-1.billybishop4-workers.xyz. With the repo checked out, bin/runnerctl apply <folder or file> [name] --port N does all of this for you.

Add your own machine

Any Linux machine with Docker can join the fleet: it takes a free machine number, gets its own tunnel, and runs every app. Get the join token from the fleet's owner (runnerctl join-token), then run on the machine:

curl -fsSL https://control.billybishop4-workers.xyz/install.sh | sudo JOIN_TOKEN=<token> sh

It runs as the container runner-agent and keeps its machine number across restarts. Remove it with docker rm -f runner-agent tunnel router.
